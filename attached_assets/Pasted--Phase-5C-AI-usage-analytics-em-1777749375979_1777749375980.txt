Phase 6A Scope:

1. الهدف

بناء طبقة تقارير وتحليلات أساسية داخل المنصة، workspace-scoped، تعتمد على البيانات الحقيقية الموجودة:

- العملاء
- المحادثات
- العمليات
- الطلبات
- المدفوعات
- الديون
- AI usage
- أداء الموظفين
- أداء القنوات

3. Backend APIs

Analytics summary:
- GET /api/analytics/overview
- GET /api/analytics/operations
- GET /api/analytics/sales
- GET /api/analytics/finance
- GET /api/analytics/ai
- GET /api/analytics/team
- GET /api/analytics/channels

Reports:
- GET /api/reports/definitions
- POST /api/reports/definitions
- PATCH /api/reports/definitions/:id
- DELETE أو archive /api/reports/definitions/:id
- POST /api/reports/generate
- GET /api/reports/generated
- GET /api/reports/generated/:id

كل API يجب أن:
- يستخدم requireSession
- يستخدم requirePermission
- يكون workspace-scoped
- لا يقبل workspace_id من body/query
- يدعم date_from/date_to
- يرجع رسائل عربية
- يسجل audit log عند إنشاء/تعديل تعريف تقرير أو توليد تقرير

4. Permissions

أضف إن كانت غير موجودة:
- analytics:read
- reports:read
- reports:create
- reports:update
- reports:delete
- reports:generate

أدوار:
- owner/manager: كل شيء
- agent: analytics:read محدود أو reports:read حسب seed
- accountant: finance analytics + reports read/generate إن مناسب
- viewer: read فقط أو حسب seed، اذكر القرار

8. Data Consistency

التقارير يمكن أن تكون query-based مباشرة من الجداول الحالية في هذه المرحلة.
لا تبنِ ETL معقد.
لا scheduled aggregation.
daily_stats يمكن أن يبقى جاهزاً أو يُملأ عند الطلب إذا كان بسيطاً.

مهم:
- لا تعرض أرقام fake.
- إذا لا توجد بيانات، اعرض 0 وحالة فارغة واضحة.
- كل رقم يجب أن يكون من DB داخل activeWorkspaceId.

9. Tests Required

Typecheck:
- pnpm run typecheck:libs
- pnpm --filter @workspace/api-server run typecheck
- pnpm --filter @workspace/web run typecheck

RBAC:
- viewer GET /api/analytics/overview → حسب seed، اذكر النتيجة
- agent GET /api/analytics/overview → حسب seed
- accountant GET /api/analytics/finance → 200 إذا seed يسمح
- viewer POST /api/reports/generate → 403 إذا لا يملك reports:generate
- owner POST /api/reports/generate → 201 أو 200
- agent POST /api/reports/definitions → 403
- owner POST /api/reports/definitions → 201

Workspace isolation:
- WS2 analytics لا يرى أرقام WS1
- WS2 generated reports لا يرى reports WS1
- workspace_id في body/query يتم تجاهله
- date filters لا تكسر العزل

Metrics:
- overview يرجع أرقام صحيحة من DB
- finance لا يحسب pending payments ضمن confirmed total
- debts open amount لا يشمل paid/written_off/cancelled
- AI usage يقرأ ai_usage / ai_runs بشكل صحيح
- team stats مرتبطة بالـ workspace فقط

Reports:
- create report definition
- generate overview report
- generated report يحتوي date range
- generated report data jsonb محفوظ
- GET generated report من workspace آخر → 404 أو 403
