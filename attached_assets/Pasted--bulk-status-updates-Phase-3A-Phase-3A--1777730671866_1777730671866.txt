ممتاز. لا تضف bulk status updates الآن، ولا تضف أي ميزة جديدة.

قبل قبول Phase 3A، نحتاج Phase 3A Closure Verification Report كامل بالأدلة والاختبارات.

كذلك لاحظت أن الملخص ذكر تفعيل أزرار:
- تذكرة
- مهمة
- متابعة

لكنه لم يذكر زر:
- فرصة

وكانت Phase 3A تشمل إنشاء Opportunity من Inbox ومن ملف العميل. إذا لم يكن زر "فرصة" مفعلاً، نفّذه كتصحيح داخل Phase 3A فقط، وليس كميزة جديدة.

المطلوب الآن:

1. Changed Files
اعرض كل الملفات التي تغيرت:
- db schema
- backend routes
- frontend pages
- shared utils
- seed/permissions

2. Database Changes
اعرض الجداول والأعمدة الجديدة أو المعدلة فعلياً:
- tickets
- tasks
- followups
- opportunities

خصوصاً:
- conversation_id
- source_message_id
- contact_id
- assigned_to أو assigned_membership_id
- team_id
- due_at
- status
- priority
- completed_by
- skipped_reason
- lost_reason
- notes

وضح إن كان هناك اختلاف بين أسماء أعمدة DB وأسماء API، وكيف عالجته.

3. Routes + Permissions
اعرض كل routes والصلاحية المطلوبة لها:

Tickets:
- GET
- POST
- GET/:id
- PATCH/:id
- PATCH/:id/status
- DELETE أو close

Tasks:
- GET
- POST
- GET/:id
- PATCH/:id
- PATCH/:id/status
- DELETE أو cancel

Followups:
- GET
- POST
- GET/:id
- PATCH/:id
- PATCH/:id/status
- DELETE أو skip/cancel

Opportunities:
- GET
- POST
- GET/:id
- PATCH/:id
- PATCH/:id/stage
- DELETE أو mark lost

4. Typecheck
شغّل واعرض النتائج:
- pnpm --filter @workspace/api-server run typecheck
- pnpm --filter @workspace/web run typecheck
- pnpm run typecheck:libs إن لزم

5. RBAC Tests
اختبر واعرض status code والرسائل العربية:

- viewer GET /api/tickets → 200
- viewer POST /api/tickets → 403
- agent POST /api/tickets → 201
- viewer POST /api/tasks → 403
- agent POST /api/tasks → 201
- viewer POST /api/followups → 403
- agent POST /api/followups → 201
- viewer POST /api/opportunities → 403
- agent POST /api/opportunities → 201
- viewer PATCH status لأي عملية → 403
- owner/manager ينجحان في تحديث الحالات حسب الصلاحيات

6. Workspace Isolation
اختبر:
- POST ticket/task/followup/opportunity مع workspace_id مختلف في body → يتم تجاهله
- إنشاء operation على contact من workspace آخر → 404 أو 403
- إنشاء operation على conversation من workspace آخر → 404 أو 403
- إنشاء operation على source_message من workspace آخر → 404 أو 403

7. State Machines
اختبر الحالات التالية:

Tickets:
- new → open ✅
- open → in_progress ✅
- in_progress → waiting_on_customer ✅
- waiting_on_customer → in_progress ✅
- in_progress → resolved ✅
- resolved → closed ✅
- closed → open يجب أن يفشل

Tasks:
- pending → in_progress ✅
- in_progress → done ✅
- done → pending يجب أن يفشل
- pending → cancelled ✅
- cancelled → pending يجب أن يفشل

Followups:
- pending → done ✅
- pending → skipped بدون skipped_reason يجب أن يفشل 400
- pending → skipped مع skipped_reason ✅
- pending → overdue ✅
- done/skipped terminal

Opportunities:
- new → qualified ✅
- qualified → proposal ✅
- proposal → negotiation ✅
- negotiation → won ✅
- أي non-terminal → lost بدون lost_reason يجب أن يفشل 400
- lost مع lost_reason ✅
- won/lost terminal

8. Quick Actions
اختبر من Inbox / Conversation:
- إنشاء ticket مرتبط بـ contact_id + conversation_id
- إنشاء task مرتبط بـ contact_id + conversation_id
- إنشاء followup مرتبط بـ contact_id + conversation_id
- إنشاء opportunity مرتبط بـ contact_id + conversation_id

اختبر من Contact Profile:

- إنشاء task مرتبط بـ contact_id
- إنشاء followup مرتبط بـ contact_id
- إنشاء opportunity مرتبط بـ contact_id
