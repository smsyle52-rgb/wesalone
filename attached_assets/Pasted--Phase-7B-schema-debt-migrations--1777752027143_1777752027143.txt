Scope:

1. افحص البيانات الحالية

افحص:

افحص:
- tickets.team_id
- conversations.team_id
- هل القيم null؟

- هل توجد قيم نصية غير UUID؟

2. is_archived migration plan

إن كانت القيم آمنة:
اقترح SQL مثل:
ALTER TABLE report_definitions
ALTER COLUMN is_archived TYPE boolean
USING (is_archived = 'true');

ثم:
ALTER TABLE report_definitions
ALTER COLUMN is_archived SET DEFAULT false;

لكن لا تطبقه إلا بعد عرض الخطة.

3. team_id migration plan

لا تفترض أن التحويل آمن.

المطلوب:
- تقرير عن عدد السجلات التي فيها team_id
- عدد null
- عدد valid UUID
- عدد invalid UUID
- عدد orphan team_id لا يطابق teams.id

إذا كل القيم آمنة:
اقترح migration:
- ALTER COLUMN TYPE uuid USING team_id::uuid
- ADD FK إلى teams(id)
- nullable يبقى nullable إذا كان هذا التصميم الحالي

إذا توجد قيم غير صالحة:
لا تطبق migration.
اقترح cleanup strategy:
- set invalid team_id to null
- أو mapping يدوي
- أو migration منفصلة بعد موافقة
