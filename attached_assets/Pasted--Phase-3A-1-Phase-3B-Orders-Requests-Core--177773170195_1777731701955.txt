3. State Machine

Orders:
- new → confirmed
- confirmed → processing
- processing → ready
- ready → delivered
- delivered → returned
- new → cancelled
- confirmed → cancelled
- processing → cancelled
- ready → cancelled

قواعد:
- delivered terminal إلا returned
- returned terminal
- cancelled terminal
- cancelled يتطلب cancel_reason إذا كانت الحالة ليست new
- returned يتطلب returned_reason
- confirmed_at يُسجّل عند new → confirmed
- delivered_at يُسجّل عند ready → delivered
- cancelled_at يُسجّل عند cancelled

لا تسمح بحالات خارج هذه القائمة.

4. Backend APIs

Orders:
- GET /api/orders
- POST /api/orders
- GET /api/orders/:id
- PATCH /api/orders/:id
- PATCH /api/orders/:id/status
- DELETE /api/orders/:id أو PATCH cancel حسب الموجود

Order Items:
- GET /api/orders/:id/items
- POST /api/orders/:id/items
- PATCH /api/orders/:id/items/:itemId
- DELETE /api/orders/:id/items/:itemId

كل API يجب أن:
- يستخدم requireSession
- يستخدم requirePermission المناسب
- يكون workspace-scoped
- لا يقبل workspace_id من body/query
- يتحقق أن contact_id و conversation_id و opportunity_id و source_message_id داخل نفس workspace
- يرجع رسائل عربية
- يسجل audit log للكتابة
- يضيف contact_timeline event عند وجود contact_id

5. Permissions

10. اختبارات إلزامية

Typecheck:
- pnpm --filter @workspace/api-server run typecheck
- pnpm --filter @workspace/web run typecheck
- pnpm run typecheck:libs إن لزم

RBAC:
- viewer GET /api/orders → 200
- viewer POST /api/orders → 403
- agent POST /api/orders → 201 إذا seed يسمح
- viewer PATCH /api/orders/:id/status → 403
- owner PATCH /api/orders/:id/status → 200
- accountant POST /api/orders → 403 أو حسب seed، اذكر النتيجة

Workspace isolation:
- POST order مع workspace_id مختلف في body → يتجاهله
- إنشاء order على contact من workspace آخر → 404 أو 403
- إنشاء order على conversation من workspace آخر → 404 أو 403
- إنشاء order على opportunity من workspace آخر → 404 أو 403
- إضافة item إلى order من workspace آخر → 404 أو 403

State machines:
- new → confirmed ✅
- confirmed → processing ✅
- processing → ready ✅
- ready → delivered ✅
- delivered → returned بدون returned_reason → 400
- delivered → returned مع returned_reason ✅
- confirmed → cancelled بدون cancel_reason → 400
- confirmed → cancelled مع cancel_reason ✅
- cancelled → confirmed يجب أن يفشل
- returned → delivered يجب أن يفشل

Order items:
- إنشاء item يحسب total = quantity * unit_price
- تعديل quantity أو unit_price يعيد حساب total
- حذف item يحدث total_amount للطلب
- total_amount في order يساوي مجموع البنود ناقص discount

Quick actions:
- من conversation يتم إنشاء order مرتبط بـ contact_id + conversation_id
- من contact profile يتم إنشاء order مرتبط بـ contact_id
- من opportunity won يتم إنشاء order مرتبط بـ opportunity_id

Audit/Timeline:
- order create يسجل audit + timeline
- item add يسجل audit
- status change يسجل audit + timeline
- cancel يسجل audit + timeline

UI:
- OrdersPage RTL
- loading/empty/error/retry موجودة
- permission denied موجود
- زر تسجيل دفعة disabled مع سبب عربي
- زر إنشاء دين غير موجود أو disabled
- لا نصوص إنجليزية للمستخدم
