ممتاز. نوافق على Phase 6A و Phase 6A.1 ونعتبرهما مغلقتين رسمياً.

الآن ابدأ Phase 7A فقط:
Production Hardening — تثبيت الإنتاج.

ممنوع في هذه المرحلة:
- لا تضف features جديدة
- لا تضف Dashboard widgets
- لا تضف Export
- لا تضف Scheduled reports
- لا تضف AI reports
- لا تضف Automation
- لا تضف Voice
- لا تضف Integrations خارجية
- لا تغيّر تجربة المستخدم إلا لإصلاح خطأ أو تحسين أمان/استقرار

Phase 7A Scope:

1. الهدف

تحويل المشروع من build feature-heavy إلى أساس إنتاج مستقر:
- migrations قابلة للتتبع
- env validation
- secrets safety
- health/readiness checks
- error handling
- logging
- rate limits أساسية
- request IDs
- security headers
- DB safety
- production checklist
- Replit deployment readiness
- Google Cloud readiness لاحقاً

2. Database / Migrations

المشكلة الحالية:
استخدمنا drizzle push كثيراً خلال التطوير.

المطلوب:
- افحص حالة Drizzle migrations الحالية.
- إن كانت migration files غير موجودة أو غير كافية:
  - لا تعمل destructive reset
  - لا تحذف بيانات
  - أضف خطة migration production واضحة في replit.md
  - إن أمكن توليد migration snapshot آمن من schema الحالي
- وثّق:
  - أن drizzle push للتطوير فقط
  - الإنتاج يحتاج migration files deterministic قبل Cloud SQL
  - ممنوع destructive migrations

لا تغيّر schema كبير الآن إلا لو خطأ واضح.

3. Env Validation

أضف أو ثبّت env validation للـ backend:
- NODE_ENV
- DATABASE_URL
- SESSION_SECRET
- GEMINI_API_KEY optional
- PORT
- CORS_ORIGIN optional
- STORAGE_PROVIDER optional
- GCS_BUCKET optional لاحقاً

قواعد:
- لا يشتغل production بدون DATABASE_URL
- لا يشتغل production بدون SESSION_SECRET قوي
- Gemini key optional
- لا تطبع secrets في logs
- error message عربي أو واضح داخلياً دون كشف السر

4. Health / Readiness

ثبّت endpoints:
- GET /api/healthz
- GET /api/readyz

healthz:
- يرجع status ok إذا السيرفر يعمل

readyz:
- يتحقق من DB connectivity
- يتحقق من وجود الجداول الأساسية إن كان بسيطاً
- لا يكشف secrets
- يرجع 503 إذا DB غير متاحة

5. Logging + Request ID

أضف:
- request_id لكل request
- middleware يضيف X-Request-Id
- logs تحتوي:
  - request_id
  - method
  - path
  - status
  - duration
  - user_id إن وجد
  - workspace_id إن وجد

لا تطبع:
- session cookie
- passwords
- tokens
- GEMINI_API_KEY
- secrets
- request body كامل للمدفوعات أو auth

6. Error Handling

ثبّت global error handler:
- Zod validation → 400 برسالة عربية مناسبة
- Auth missing → 401
- Permission denied → 403
- Not found → 404
- Business rule violation → 422
- Unexpected error → 500 برسالة عامة:
  "حدث خطأ غير متوقع"
- logs الداخلية تحتوي request_id

7. Security Headers

أضف headers أساسية:
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY أو SAMEORIGIN حسب الحاجة
- Referrer-Policy
- Permissions-Policy
- basic Helmet إن كان مناسباً

لا تكسر Vite/frontend.

8. Rate Limits

أضف rate limiting بسيط:
- auth login/register
- AI run endpoints
- payment confirm/reject
- report generate

لا تجعله معقداً.
الهدف منع abuse أساسي.

رسائل عربية:
"عدد المحاولات كبير، حاول لاحقاً"

9. Session / Cookie Safety

راجع إعدادات session:
- httpOnly
- sameSite
- secure في production
- expiration واضح
- لا expose session token في frontend

10. CORS

راجع CORS:
- development يسمح localhost/Replit preview
- production يستخدم CORS_ORIGIN إن وجد
- لا wildcard في production إذا credentials true

11. RBAC Audit

اعمل فحص ثابت:
- كل route داخل modules المهمة يستخدم requireSession
- كل route تشغيلية يستخدم requirePermission
- لا route مالية أو AI أو reports بدون permission
- healthz/readyz فقط public

12. Workspace Isolation Audit

اعمل فحص ثابت:
- لا استخدام لـ req.body.workspaceId في routes
- لا استخدام لـ req.query.workspaceId لتحديد workspace
- activeWorkspaceId من session فقط
- اذكر أي استثناء إن وجد

13. Secrets Scan

اعمل grep أو فحص:
- GEMINI_API_KEY
- api_key
- secret
- token
- password
- private_key

وتأكد:
- لا توجد secrets hardcoded
- لا logs تطبعها
- DB يخزن secret refs فقط إن وجدت

14. Frontend Stability

أضف أو ثبّت:
- ErrorBoundary عام
- صفحة 404
- fallback loading
- session expired redirect واضح
- لا crash أبيض

لا تضف features.

15. Deployment Notes

حدّث replit.md:
- كيف نشغل dev
- كيف نشغل typecheck
- كيف نشغل db push/migrations في dev
- env المطلوبة
- ما هو المؤجل قبل الإنتاج الحقيقي
- Google Cloud readiness notes:
  - Cloud SQL
  - Secret Manager
  - Cloud Storage
  - Cloud Run
  - migrations قبل الإنتاج
  - backup/PITR لاحقاً

16. Tests Required

Typecheck:
- pnpm run typecheck:libs
- pnpm --filter @workspace/api-server run typecheck
- pnpm --filter @workspace/web run typecheck

Health:
- GET /api/healthz → 200
- GET /api/readyz → 200 مع DB شغالة
- readyz بدون DB أو DB خطأ → 503 إن أمكن اختباره

Auth/security:
- login rate limit يعمل
- missing session → 401
- forbidden route → 403
- validation error → 400
- business violation → 422
- unexpected error لا يكشف stack للمستخدم

RBAC:
- افحص قائمة routes العامة والخاصة
- أكد أن healthz/readyz فقط public

Workspace:
- grep req.body.workspaceId
- grep req.query.workspaceId
- اذكر النتائج

Secrets:
- grep للـ keys/secrets
- لا GEMINI key hardcoded
- لا password seed في production path

Logging:
- response يحتوي X-Request-Id
- logs لا تحتوي secrets

Frontend:
- route غير موجود → 404
- session expired → login
- ErrorBoundary يعمل أو موجود
