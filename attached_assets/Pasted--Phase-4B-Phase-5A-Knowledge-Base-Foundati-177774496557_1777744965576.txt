Knowledge Base Foundation — قاعدة المعرفة.

Phase 5A Scope:

1. الهدف

بناء قاعدة معرفة داخلية قابلة للاستخدام لاحقاً مع Gemini/RAG، لكن بدون تشغيل Gemini الآن.

يجب دعم:
- Knowledge bases
- Knowledge sources
- Knowledge documents
- Knowledge chunks
- FAQ entries
- Processing status
- Versioning بسيط أو updated_at
- RBAC
- Workspace isolation
- Audit logs
- UI عربية RTL

2. Database / Schema

أضف أو ثبّت الجداول التالية:

knowledge_bases:
- id
- workspace_id
- name
- description nullable
- status: active | archived
- created_by
- created_at
- updated_at

- id

knowledge_documents:

knowledge_chunks:

- لا تضف embeddings فعلية الآن.
- embedding_status يكون pending أو skipped.
- embeddings_index_reference يكون not_configured افتراضياً.
- لا تستدعِ Gemini.
- لا تستدعِ أي API خارجي.

3. Chunking Logic

أضف chunking بسيط محلي فقط:
- عند إنشاء knowledge document من نص طويل:
  - قسم النص إلى chunks بطول آمن تقريباً
  - chunk_index يبدأ من 0
  - لا embeddings
  - embedding_status = pending أو skipped حسب التصميم
- لا تستخدم AI للتقسيم.
- لا تستخدم OCR.
- لا file parsing معقد الآن.

4. Backend APIs

Knowledge Bases:
- GET /api/knowledge/bases
- POST /api/knowledge/bases
- GET /api/knowledge/bases/:id
- PATCH /api/knowledge/bases/:id
- DELETE أو archive /api/knowledge/bases/:id

Sources:
- GET /api/knowledge/bases/:id/sources
- POST /api/knowledge/bases/:id/sources
- PATCH /api/knowledge/sources/:sourceId
- DELETE أو archive /api/knowledge/sources/:sourceId

Documents:
- GET /api/knowledge/bases/:id/documents
- POST /api/knowledge/bases/:id/documents
- GET /api/knowledge/documents/:documentId
- PATCH /api/knowledge/documents/:documentId
- DELETE أو archive /api/knowledge/documents/:documentId

Chunks:
- GET /api/knowledge/documents/:documentId/chunks
- POST /api/knowledge/documents/:documentId/rechunk

FAQ:
- GET /api/knowledge/bases/:id/faqs
- POST /api/knowledge/bases/:id/faqs
- PATCH /api/knowledge/faqs/:faqId
- DELETE أو archive /api/knowledge/faqs/:faqId

Search:
- GET /api/knowledge/search?q=...
بحث نصي بسيط فقط داخل نفس workspace.
لا embeddings.
لا AI.

كل API يجب أن:
- يستخدم requireSession
- يستخدم requirePermission
- يكون workspace-scoped
- لا يقبل workspace_id من body/query
- يرجع رسائل عربية
- يسجل audit log للكتابة

5. Permissions

أضف إذا كانت غير موجودة:
- knowledge:read
- knowledge:create
- knowledge:update
- knowledge:delete
- knowledge:manage

أدوار مبدئية:
- owner/manager: كل شيء
- agent/support/sales: read فقط
- viewer: read فقط أو لا حسب seed، اذكر القرار
- accountant: غالباً لا يحتاج إلا إذا seed الحالي يسمح read

9. Tests Required

Typecheck:
- pnpm run typecheck:libs
- pnpm --filter @workspace/api-server run typecheck
- pnpm --filter @workspace/web run typecheck

RBAC:
- viewer GET /api/knowledge/bases → حسب seed، اذكر النتيجة
- viewer POST /api/knowledge/bases → 403
- agent GET /api/knowledge/bases → 200 إذا seed يسمح read
- agent POST /api/knowledge/bases → 403
- owner POST /api/knowledge/bases → 201
- owner POST document → 201
- owner POST FAQ → 201

Workspace isolation:
- knowledge base من workspace آخر → 404 أو 403
- document من workspace آخر → 404 أو 403
- FAQ من workspace آخر → 404 أو 403
- workspace_id في body يتم تجاهله

Chunking:
- document طويل ينشئ chunks
- chunk_index صحيح
- إعادة التقسيم تحذف/تستبدل chunks القديمة بشكل آمن
- embedding_status ليس embedded

Search:
- البحث يجد كلمة موجودة في FAQ
- البحث يجد كلمة موجودة في document/chunk
- البحث لا يرجع نتائج من workspace آخر

Audit:
- create/update/archive للمعرفة تسجل audit
- rechunk يسجل audit

UI:
- KnowledgePage RTL
- إنشاء قاعدة معرفة يعمل
- إنشاء وثيقة نصية يعمل
- FAQ يعمل
- search يعمل
- file/url buttons disabled مع سبب عربي
- لا يوجد Gemini أو AI UI
