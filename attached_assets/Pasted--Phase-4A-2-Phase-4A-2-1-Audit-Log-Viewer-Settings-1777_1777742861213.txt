Phase 4B Scope:

1. الهدف

بناء نظام ديون وتحصيل يدوي مرتبط بـ:
- العملاء
- الطلبات
- المدفوعات
- المبالغ المتبقية
- تواريخ الاستحقاق
- ملاحظات التحصيل
- حالة الدين
- contact timeline
- audit logs

الدين هنا ليس بوابة دفع ولا تمويل. هو سجل ذمم/مبلغ مستحق على العميل.

2. Database / Schema

أضف أو ثبّت جدول debts:

- contact_id
- order_id nullable
- source_payment_id nullable

- status: open | partial | paid | overdue | written_off | cancelled
- due_at nullable

- notes nullable
- created_by

- paid_at nullable
- written_off_at nullable
- cancelled_at nullable

collection_notes:
- id
- workspace_id
- debt_id

مهم:
- لا تجعل debt يغيّر order.paid_amount مباشرة.
- المدفوعات المؤكدة هي التي تغيّر paid_amount.
- debt يعكس المبلغ المستحق والمتابعة والتحصيل.
- لا تضف debt تلقائياً إلا بزر واضح من المستخدم.

3. State Machine

Debts:
- open → partial
- open → paid
- open → overdue
- open → written_off
- open → cancelled
- partial → paid
- partial → overdue
- partial → written_off
- partial → cancelled
- overdue → partial
- overdue → paid
- overdue → written_off
- overdue → cancelled

قواعد:
- paid terminal
- written_off terminal ويتطلب write_off_reason
- cancelled terminal ويتطلب cancel_reason
- written_off لا يحدث إلا owner/manager أو permission debts:write_off
- cancelled لا يحدث إلا owner/manager أو permission debts:cancel
- remaining_amount لا يكون أقل من 0

4. Backend APIs

Debts:
- GET /api/debts
- POST /api/debts
- GET /api/debts/:id
- PATCH /api/debts/:id
- PATCH /api/debts/:id/status
- DELETE /api/debts/:id أو cancel حسب التصميم

Collection Notes:
- GET /api/debts/:id/notes
- POST /api/debts/:id/notes
- PATCH /api/debts/:id/notes/:noteId
- DELETE /api/debts/:id/notes/:noteId

كل API يجب أن:
- يستخدم requireSession
- يستخدم requirePermission
- يكون workspace-scoped
- لا يقبل workspace_id من body/query
- يتحقق أن contact_id/order_id/payment_id داخل نفس workspace
- يرجع رسائل عربية
- يسجل audit log للكتابة
- يضيف contact_timeline event

5. Permissions

- collection_notes:read

أدوار مبدئية:

- viewer: read فقط

6. Order Integration

من Order Detail:
- إذا remaining_amount > 0:
  - زر "إنشاء دين" مفعّل لمن يملك debts:create
  - يملأ contact_id + order_id + amount = remaining_amount + currency تلقائياً
- إذا order paid بالكامل:
  - الزر disabled:
    "لا يوجد مبلغ متبقٍ على هذا الطلب"
- إذا order cancelled/returned:
  - الزر disabled:
    "لا يمكن إنشاء دين على طلب ملغي أو مرتجع"

لا تنشئ الدين تلقائياً.
يجب أن يضغط المستخدم زر واضح.

9. Payments Integration

عند confirm payment مرتبط بـ order:
- لا تغيّر debts تلقائياً في هذه المرحلة إلا إذا كان التنفيذ بسيطاً وآمناً جداً.
- الأفضل الآن: أضف تنبيه UI إذا كانت هناك ديون مرتبطة بالطلب:
  "يوجد دين مرتبط بهذا الطلب، راجع حالة الدين بعد تأكيد الدفعة"

إذا قررت تحديث debt عند الدفع:
- يجب أن يكون داخل transaction
- يجب أن يحدّث remaining_amount
- إذا remaining_amount = 0 يجعل status=paid
لكن لا تفعل ذلك إذا سيعقّد المرحلة.

الأفضل لهذه المرحلة: manual debt settlement عبر PATCH debt/status أو update remaining_amount بصلاحية accountant/manager.

RBAC:
- viewer GET /api/debts → 200
- viewer POST /api/debts → 403
- agent POST /api/debts → حسب seed، اذكر النتيجة
- accountant POST /api/debts → 201 إذا seed يسمح
- viewer PATCH /api/debts/:id/status → 403
- accountant PATCH /api/debts/:id/status → حسب seed
- agent POST /api/debts/:id/notes → حسب seed
- viewer POST /api/debts/:id/notes → 403

Workspace isolation:
- POST debt مع workspace_id مختلف في body → يتم تجاهله
- debt على contact من workspace آخر → 404 أو 403
- debt على order من workspace آخر → 404 أو 403
- note على debt من workspace آخر → 404 أو 403

State machine:
- open → partial ✅
- partial → paid ✅
- open → overdue ✅
- overdue → paid ✅
- open → written_off بدون reason → 400
- open → written_off مع reason ✅
- open → cancelled بدون reason → 400
- open → cancelled مع reason ✅
- paid → open يجب أن يفشل
- written_off → open يجب أن يفشل
- cancelled → open يجب أن يفشل

Order integration:
- order remaining > 0 → create debt works
- paid order → create debt disabled أو API يمنعها
- cancelled/returned order → create debt disabled أو API يمنعها

Validation:
- amount <= 0 → 400
- remaining_amount > amount → 400
- due_at في الماضي يسمح لكنه يجعل debt overdue حسب logic أو يوضح الحالة
- currency يجب أن تكون YER/SAR/USD

Audit/Timeline:
- debt create audit + timeline
- debt status change audit + timeline
- collection note audit + timeline
- write off audit severity warning أو critical

UI:
