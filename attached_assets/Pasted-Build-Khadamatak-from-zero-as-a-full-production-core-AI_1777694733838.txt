Build Khadamatak from zero as a full production-core AI Customer Operations SaaS platform with functional parity to Gabster-like platforms, localized for Yemen.

Important:
Do not build a small MVP.
Do not build a chatbot only.
Do not build a CRM only.
Do not build Shopify.
Do not build ERP.
Do not build a sector-specific app.
Build a complete platform core.

Gabster-like functional category:
Communication + Operations + Analytics + Action.
The platform must include customer communication, unified inbox, AI agents, knowledge base, human handoff, tickets, tasks, follow-ups, sales opportunities, orders/requests, manual payments, debts/collection, workflow automation, analytics, reports, team management, channels, integrations shell, billing/usage, settings, and audit logs.

Localization difference:
Gabster is focused on Saudi/Gulf.
Khadamatak is focused on Yemen.
So implement Yemeni localization:
- Arabic RTL
- Yemeni dialect settings for AI agents
- Yemeni manual payments
- YER, SAR, USD
- manual exchange rates
- cash, transfer, Kuraimi, Jawali, bank
- partial payments
- debts
- collection tracking
- weak internet
- mobile-first PWA-ready UI
- WhatsApp manual workflows before official WhatsApp API

Architecture:
Use a stable modular monolith suitable for Replit:
- React + Vite + TypeScript frontend
- Tailwind CSS
- Arabic RTL mobile-first UI
- Node.js + Express + TypeScript backend
- PostgreSQL database
- Drizzle ORM
- Zod validation
- Session-based authentication
- RBAC permissions
- Workspace-based multi-tenancy
- Audit logs
- AI adapter for Gemini
- Storage adapter
- Integration adapter pattern
- Single external web server port

The core is not WhatsApp.

Workspace → Contact → Conversation → Message → AI Understanding → Action → Report.

tickets, tasks, follow-ups, opportunities, orders, payments, debts, workflow runs, notifications, reports.

Meta rule:
There is an old platform under Meta review, but this new platform must not depend on it.
Do not import old code.
Do not implement live WhatsApp API now.
Do not implement Meta OAuth now.
Do not implement Embedded Signup now.
Create a pending Meta/WhatsApp integration shell only:
status = Pending Meta Review.
Manual WhatsApp, copy/paste, wa.me, and website widget are active.

Payment rule:
Do not implement external payment providers now.
Implement Yemeni manual payment management fully:
cash, transfer, Kuraimi, Jawali, bank, partial payment, debt, collection, exchange rate, receipt attachment, approval workflow.
Every payment starts as pending.
Only Owner, Manager, or Accountant can confirm payments.
AI must never confirm payments or change financial states.

AI rule:
AI agents are operational copilots.
They can summarize, classify, extract, draft replies, suggest tasks, suggest tickets, suggest opportunities, suggest orders, suggest follow-ups, generate reports.
AI must not:
- delete data
- send messages automatically
- confirm payments
- change financial states
- change permissions
- activate external integrations
Every AI run must be logged with usage.

Security:
Every operational table must include workspace_id.
Never query tenant data without workspace_id.
Do not accept workspace_id from request body.
Use active workspace from session context.
Every important action must create audit log.
No secrets in code.
No destructive migrations.
No fake production data.

UI rules:
Arabic RTL only for end users.
Mobile-first.
Every screen must have an empty state.
Every button must work or be disabled with a clear Arabic reason.
No dead pages.
No broken navigation.
No English labels visible to normal users.
No lorem ipsum.

Before coding:
Create a detailed architecture plan only.
Include:
1. App structure
2. Database schema
3. Permission model
4. Routing structure
5. UI navigation
6. Full module map
7. Implementation order
8. Acceptance tests
9. Risks and safeguards

Do not start coding until the plan is approved.
