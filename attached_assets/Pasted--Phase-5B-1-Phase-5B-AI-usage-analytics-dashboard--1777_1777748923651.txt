Phase 5C Scope:

1. الهدف

تفعيل Gemini provider في طبقة AI الموجودة، مع:
- استخدام GEMINI_API_KEY من environment variable فقط
- fallback تلقائي إلى mock إذا المفتاح غير موجود أو فشل الطلب
- تسجيل provider/model في ai_runs
- تسجيل tokens إن أمكن
- المحافظة على كل safety guards الحالية
- لا auto-send
- لا تنفيذ actions حساسة

2. Provider Adapter

حدّث ai-provider.ts فقط أو بأقل تغييرات ممكنة:

- إذا process.env.GEMINI_API_KEY موجود:
  استخدم Gemini provider
- إذا غير موجود:
  استخدم mock provider كما هو
- إذا Gemini request فشل:
  سجل error في ai_run أو provider metadata
  استخدم mock fallback إذا كان ذلك آمناً
  أظهر رسالة عربية واضحة:
  "تعذر الاتصال بـ Gemini، تم استخدام الوضع التجريبي"

3. Model Mapping

ادعم أسماء داخلية:
- gemini_flash
- gemini_flash_lite
- gemini_pro
- mock

اربطها بأسماء Gemini الفعلية في مكان واحد داخل adapter.
لا تكرر أسماء الموديلات في routes.

4. Structured Output Safety

لمهام:
- classify
- extract
- suggest_actions

حاول إجبار output على JSON منظم.
إذا رجع Gemini نصاً غير صالح:
- لا تكسر endpoint
- سجّل ai_run.status = failed أو fallback إلى mock
- رجع رسالة عربية واضحة
- لا تنفذ أي action

5. Prompt Safety

أضف system/developer instructions داخل provider:
- لا ترسل رسائل تلقائياً
- لا تؤكد أو ترفض مدفوعات

- لا تغيّر صلاحيات

- اللهجة حسب agent.dialect

- completion_tokens
- total_tokens
- provider=gemini
