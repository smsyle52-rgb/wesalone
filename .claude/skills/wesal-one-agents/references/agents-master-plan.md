## القسم 1 — نموذج الوكيل المعتمد: "الموظف الذكي" (ما يقوله السوق)

كل المنصات الناجحة تتفق على نفس النموذج، ووصال ون يتبعه:

### 1.1 هوية الوكيل (لكل وكيل في الـ workspace)
- **اسم بشري** (مثل "احمد") — لا يعرّف نفسه كذكاء اصطناعي (نهج برايد المجرَّب).
- **دور**: مبيعات / دعم / حجوزات — يُربط بملفات القطاعات الست الموجودة.
- **لهجة ونبرة**: حقل تعليمات اللهجة (صنعاني/خليجي/فصحى...).
- **تعليمات مخصصة**: نص حر من التاجر يُحقن في الـ system prompt.

### 1.2 المعرفة (Grounding)
- الوكيل يجيب **من قواعد المعرفة المربوطة فقط** — لا اختلاق. (معيار Lyro/السوق).
- المصادر: كتالوج المنتجات (Meta catalog mirror الموجود) + معرفة النشاط + أسئلة شائعة Q&A.
- إن لم يجد إجابة → لا يخترع: يسأل توضيحاً أو يصعّد للبشر (قاعدة handoff).

### 1.3 الاستقلالية: تلقائي-أولاً مع حواجز
- **الوضع الافتراضي: رد تلقائي كامل** (نموذج برايد المُثبت: 7-10 معاملات/يوم بلا تدخل).
- **وضع ثانوي: مسودة بموافقة** — يبقى متاحاً لكل وكيل (المنطق موجود في draft-reply).
- **بوابة الثقة (trust gate) الموجودة تبقى** حارساً قبل أي إرسال تلقائي.

### 1.4 التولّي البشري (Human Takeover) — قاعدة السوق الذهبية
- **لحظة ما يرسل بشري رداً يدوياً في محادثة → الوكيل يتوقف فيها فوراً.**
- مدة الإيقاف: 30 دقيقة افتراضياً (قابلة للضبط لكل وكيل)، أو حتى يضغط التاجر "أعد الوكيل".
- **حرج — وضع Coexistence:** رد التاجر من تطبيق واتساب نفسه يصل كـ echo — **يُحتسب تولّياً بشرياً ويوقف الوكيل**. (هذا فخ موثّق في شكاوى منصات منافسة؛ برايد يعمل Coexistence فلا تهاون فيه).
- الوارد يعرض حالة المحادثة: 🤖 الوكيل يرد / ⏸️ موقوف مؤقتاً (حتى hh:mm) / 👤 بشري — مع زرّي "أوقف الوكيل" / "أعد الوكيل".

### 1.5 قواعد التصعيد (Handoff)
- كلمات مفتاحية ("أكلم إنسان"، "مدير"، شكوى...) → إيقاف الوكيل + إشعار للتاجر.
- عجز متكرر (سؤالان بلا إجابة من المعرفة) → تصعيد.
- التصعيد يحفظ كامل السياق — البشري يكمل من نفس المحادثة (معيار respond.io).

### 1.6 ربط القناة بالوكيل
- كل قناة (رقم واتساب/حساب إنستغرام/صفحة) لها **وكيل افتراضي** يُختار من إعدادات القناة.
- المحادثة ترث وكيل قناتها، مع إمكانية override لمحادثة بعينها.

### 1.7 الوكيل "موظف مهمات" لا "بوت ردود" — التمايز ضد Meta Business Agent
الوكيل يملك **أدوات** ينفّذ بها أفعالاً حقيقية (function calling عبر Vertex/Gemini):
| الأداة | تستدعي | الـ backend |
|---|---|---|
| `create_order` | إنشاء طلب من المحادثة | orders.routes (موجود ✅) |
| `log_payment_claim` | تسجيل ادعاء دفع/حوالة للمراجعة | payments.routes (موجود ✅) |
| `schedule_followup` | جدولة متابعة (عميل قال "بكرة") | متابعات الواردة في لوحة الإحصائيات |
| `send_product_media` | إرسال صور/فيديو منتج | الكتالوج + outbox |
| `handoff_to_human` | تصعيد فوري | قاعدة 1.5 |
هذه الأدوات هي الخندق: ميتا تعطي ردوداً عامة؛ وصال ون يعطي موظفاً ينجز.

### 1.8 الاختبار قبل التشغيل + التحسين المستمر
- Playground الموجود يبقى بوابة إلزامية: لا يُفعَّل وكيل على قناة قبل اجتياز اختبار محادثة كاملة.
- التحسين: مراجعة المحادثات الفعلية → إضافة المعرفة الناقصة → (لاحقاً) اقتراحات تلقائية من المحادثات.
- متابعة صامتة (Follow-up nudge): إن صمت العميل بعد اهتمام شرائي → رسالة متابعة واحدة مهذبة (معيار respond.io؛ يتكامل مع قاعدة برايد: لا إلحاح بعد رفض واضح).

## القسم 2 — معمارية حلقة الرد (التصميم التقني الملزم)

```
رسالة واردة (webhook) → تُحفظ + domain_event: message.received
        ↓
agent-runner (حلقة استهلاك داخل عملية outbox-worker — لا خدمة جديدة)
        ↓ يتحقق بالترتيب:
  [1] القناة لها وكيل مفعّل؟        لا → توقف
  [2] المحادثة بوضع بشري/موقوفة؟    نعم → توقف
  [3] داخل نافذة إيقاف takeover؟    نعم → توقف
  [4] الرسالة echo من التاجر؟       نعم → فعّل الإيقاف 30د وتوقف
        ↓ اجتاز
  بناء السياق: تاريخ المحادثة + استرجاع من قواعد المعرفة المربوطة
        ↓
  استدعاء runAgentReply (خدمة مشتركة مستخرجة من منطق draft-reply الحالي)
        ↓
  بوابة الثقة → نجح → outbox_events (message.send.<channel>.text/media)
        ↓
  outbox-worker يرسل لميتا (المسار الموجود ✅)
```

**قرارات تقنية مقفلة:**
1. **الاستخراج لا التكرار:** منطق الرد في `ai.routes.ts` (draft-reply) يُستخرج إلى خدمة `runAgentReply()` يستدعيها كلٌّ من endpoint المسودة وحلقة agent-runner — مصدر حقيقة واحد.
2. **agent-runner داخل عملية outbox-worker** (حلقة poll ثانية على domain_events غير المعالجة) — لا deployment جديد، لا تعقيد.
3. **idempotency:** كل domain_event يُعالج مرة واحدة (علامة processed/claimed) — لا ردود مكررة.
4. **زر الوارد "اقتراح رد"** يتحول من mock إلى الوكيل الحقيقي للقناة (ميزة AI Assist بجانب الرد التلقائي).
5. **مهلة قصوى وحد رسائل:** حد أقصى ردود متتالية من الوكيل بلا رد عميل = 2 (منع loops)، ومهلة استدعاء النموذج 30 ثانية ثم تخطٍّ مسجَّل.
6. `AI_MAX_OUTPUT_TOKENS` يُرفع إلى 2048 على Cloud Run (يغلق ITEM 5 — اقتطاع الردود).

## القسم 3 — التسجيل المضمن (Embedded Signup) — المواصفة الملزمة

> يُبنى على **تطبيق الإنتاج Wesal One (App ID 1437258534807702)** — صلاحياته معتمدة الآن. التجار الجدد يدخلون على تطبيق الإنتاج مباشرة؛ برايد يبقى على تطبيق التطوير حتى ترحيل لاحق هادئ. المنصة تدعم التطبيقين مؤقتاً عبر عمود `meta_app_id` للقناة (يُغلق #19 للأمام).

### 3.1 المتطلب القبلي: محلّل التوكنات لكل عميل (Token Resolver)
- توكن كل تاجر (الناتج من التسجيل المضمن) يُخزَّن في **Secret Manager** ويُشار له بـ `credentialsSecretRef` (العمود موجود ✅).
- خدمة resolver في runtime: `resolveChannelToken(channelId)` — تقرأ من Secret Manager مع cache بالذاكرة (TTL 10 دقائق)، و**fallback** لتوكن البيئة العام للقنوات القديمة (برايد) فقط.
- تُستبدل كل مواضع `META_SYSTEM_USER_TOKEN/META_ACCESS_TOKEN` المباشرة في: `meta-graph.ts`، `outbox-worker/index.ts`، `catalog-sync` — بالresolver.

### 3.2 إعدادات لوحة ميتا (ينفّذها المالك بيده — ليست كوداً)
على تطبيق Wesal One (1437...):
1. Facebook Login for Business → Settings → تفعيل: Client OAuth login, Web OAuth login, Enforce HTTPS, Embedded Browser OAuth Login, **Login with the JavaScript SDK = Yes** (يغلق #18).
2. إضافة دومينات المنصة في **Allowed Domains for the JavaScript SDK** و **Valid OAuth Redirect URIs** (الرابط الحالي + wesal.one مستقبلاً).
3. Configurations → **Create from template: WhatsApp Embedded Signup Configuration** → حفظ **config_id**.
4. Webhooks → التأكد أن حقل **messages** مشترَك على التطبيق (شرط قبل subscribed_apps).

### 3.3 تدفق الواجهة (صفحة "ربط واتساب" في لوحة التاجر)
1. تحميل Facebook JS SDK + `FB.init({ appId: 1437..., version: 'v22.0' })`.
2. زر "اربط رقم واتساب" → `FB.login(callback, { config_id, response_type: 'code', override_default_response_type: true })`.
3. **مستمع الجلسة**: `window.addEventListener('message', ...)` من origin فيسبوك فقط — عند `type=WA_EMBEDDED_SIGNUP, event=FINISH` يلتقط `waba_id, phone_number_id, business_id` ويرسلها للـ backend.
4. الـ callback يلتقط `authResponse.code` ويرسله للـ backend (لا يُحفظ في المتصفح).

### 3.4 تدفق الـ backend (endpoint: `POST /api/integrations/embedded-signup/complete`)
بالترتيب الذرّي (مع تسجيل كل خطوة):
1. **تبادل الكود → توكن**: Graph `GET /oauth/access_token?client_id&client_secret&code` → Business Integration System User Access Token.
2. **تخزين التوكن** في Secret Manager → `credentialsSecretRef` جديد.
3. **اشتراك التطبيق بالحساب**: `POST /{waba_id}/subscribed_apps` بتوكن التاجر.
4. **تسجيل الرقم**: `POST /{phone_number_id}/register` مع PIN (تدفق 2FA؛ إن كان الرقم مسجلاً يتخطى بأمان).
5. **إنشاء صف القناة**: workspace الحالي + waba_id + phone_number_id + business_id + meta_app_id=1437... + credentialsSecretRef + الوكيل الافتراضي (يختاره التاجر في الخطوة التالية من المعالج).
6. فحص نجاح: جلب `display_phone_number` وعرضه للتاجر "تم ربط +967xxx ✅".
- **فشل أي خطوة** → rollback واضح + رسالة عربية مفهومة + سجل للدعم. لا قنوات نصف-مربوطة.

### 3.5 معالج إعداد التاجر الجديد (Onboarding Wizard — معيار السوق)
خمس خطوات متتابعة، شاشة لكل مهمة:
1. **عرّف نشاطك** (موجود في دليل التشغيل) → 2. **اربط واتساب** (التسجيل المضمن أعلاه) → 3. **أضف معرفتك** (منتجات/أسئلة شائعة — استيراد سريع) → 4. **جهّز وكيلك** (اسم، دور، لهجة، ربط المعرفة، Playground إلزامي) → 5. **فعّل** (تشغيل الوكيل على القناة + رسالة اختبار حقيقية).

## القسم 5 — المحميات (تسري على كل المراحل)
1. الوارد الشغّال واستقبال برايد — لا ينقطع ولو دقيقة.
2. بث SSE `/api/inbox/stream` يبقى network-only؛ الـ Service Worker لا يلمس `/api/*`.
3. توقيع webhook (HMAC SHA-256) قائم — لا يُضعف، ولا يُسمح بتجاوزه في الإنتاج حتى لو غاب المتغير.
4. تخطيط سطح المكتب `lg+` لا يُمس في أي تعديل واجهة.
5. عزل الـ workspace في كل استعلام جديد — بلا استثناء.
6. لا ربط/فصل قنوات برمجياً دون طلب صريح من المالك.
7. أسرار وتوكنات: Secret Manager/env فقط — لا تظهر في كود أو سجلات أو تقارير.
