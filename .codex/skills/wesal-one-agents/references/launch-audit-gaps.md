### مفتوحة ⏳ — إلزامية قبل التسجيل العام
**القنوات/الوارد/العزل:**
- ⏳ لا **Unique constraint ذري** على `(workspace_id, provider_message_id)` (فهرس عادي فقط) → Select-ثم-Insert يسمح بنسختين → أحداث/ردود وكيل مكررة.
- ⏳ `unread_count` يزيد **قبل** فحص التكرار → تكرار webhook يضخّم العدّاد.
- ⏳ **Lookup القناة عالمي** بأول صف بلا فرض تفرد `phone_number_id`/`ig`/`page` → عدة workspaces بنفس المعرّف = **توجيه رسالة لعميل خاطئ** (خرق عزل).
- ⏳ **Messenger echo** لا يُستبعد بوضوح → رسالة صادرة تدخل كوارد → **حلقة رد**.
- ⏳ قناة واتساب تصير `active` **قبل** نجاح `subscribed_apps` + تسجيل الرقم؛ التسجيل يستخدم **PIN ثابت `000000`** والفشل يرجع 201.
- ⏳ Lookup الوارد لا يشترط `status=active` للقناة.

**العزل المعماري (DB):**
- ⏳ لا Composite FK/RLS يثبت أن `conversation.contact_id` / `channel_account_id` / `message.workspace_id` من نفس الـworkspace؛ ولا على `contact_channels` / membership roles / team members.
- ⏳ اختبارات العزل الحالية تختبر SQL مقيّداً أصلاً بـworkspace_id، **لا HTTP بجلستين** فعليتين، ولا تغطي كل الجداول.

**المالية:**
- ⏳ **تأكيد الدفع**: التعليق يقول `FOR UPDATE` لكن القراءة داخل الـtransaction **لا** تستخدم `.for("update")`، ولا شرط `status='pending'` في التحديث → تأكيدان متزامنان يقرآن نفس المبلغ.
- ⏳ **أرقام الطلبات `count+1`** (يدوي ومن الوكيل) بلا Unique على `(workspace_id, order_number)` → أرقام مكررة (الكود يزيل التكرار عند العرض بدل منعه).
- ⏳ **إجمالي طلب الوكيل لا يضيف رسوم التوصيل** بينما اليدوي يضيفها → مجموع مختلف حسب المصدر.
- ⏳ خصم النقاط بعد المزود بلا **حجز مسبق** → استدعاءات متزامنة قرب نفاد الرصيد تمرّ كلها؛ وبعض المسارات بلا `aiRunId` (مفتاح بديل بـ`Date.now()`) → خصم مكرر عند retry.
- ⏳ **إيصالات الدفع في bucket عام (public-read)** → رابط الإيصال المالي مكشوف لمن يعرف الـURL (خصوصية).

**المخزون/الفريق:**
- ⏳ تعديل الكمية **read-modify-write بلا قفل** → تعديلان متزامنان يفقد أحدهما؛ والنقص تحت الصفر يصير صفراً بصمت.
- ⏳ **دعوة عضو**: كلمة المرور يحددها الداعي بلا تدفق قبول؛ مستخدم موجود يُضاف لـworkspace **بلا موافقته**.
- ⏳ تغيير الدور **غير ذري** (حذف ثم إضافة) قد يترك العضو بلا دور؛ **لا Last-owner invariant**.

## P1 — أنماط متكررة تكسر الثقة (قبل التسجيل العام)
- **لا Transactions شاملة** لأغلب مسارات الأعمال (تسجيل، محادثة واردة، طلب، دفع، معرفة، وكيل) → حالات جزئية عند فشل مرحلة.
- **لا Timeouts/AbortSignal** على أغلب الاستدعاءات الخارجية (Meta Graph، Vertex، Gemini، GCS، profile). `runAIWithTimeout` لا يمرّر Signal فعلياً.
- **Onboarding** ليس حدثاً دائماً (يُعاد حسابه كل دخول من وكيل/قناة/معرفة)؛ لا `onboarding_completed_at`؛ لا **server-side gate** (الحجب في الواجهة فقط)؛ إكمال القناة/المعرفة لا يثبت webhook/استقبال/استرجاع حقيقي.
- **تأكيد البريد**: `emailVerified` في الجلسة لا يُحدّث بعد التأكيد → المستخدم محجوب حتى خروج/دخول؛ وتغيير البريد لا يبطل جلسات/لا يعيد حساب Platform-Admin.
- **Realtime (SSE)** في ذاكرة عملية API فقط → لا يعمل مع >1 instance؛ `publishDomainEvent` يبتلع الفشل.
- **Audit** best-effort وقابل للتعديل على DB (لا قيد append-only مثبت)؛ فشل كتابته لا يفشل العملية المالية.
- **تعطيل Workspace** لا يوقف الجلسات/القنوات/الطوابير/الوكلاء ولا يحذف/يشفّر.
- **Worker health** يرجع 200 دائماً؛ **Readiness** لا تغطي Meta/AI/GCS/backlogs/migration/channels.
- **المعرفة**: `status=ready` قبل اكتمال chunks/embeddings؛ فشل Vertex → pseudo-vector يُبتلع ويُحسب اكتمالاً؛ rechunk يحذف القديم قبل إتمام الجديد؛ أرشفة المصدر لا تؤرشف وثائقه؛ بحث قد يُظهر draft/archived.
- **الهجرات**: مصدران متوازيان (Drizzle journal حتى 0031 + `migrate-phase345.sql`)؛ **الإنتاج يشغّل الأحادي فقط**؛ لا backup قبل migration؛ لا down/rollback؛ verify يفحص مجموعة مختارة لا كل القيود.
- **النشر**: خدمة الإنتاج اسمها `khadamatak-staging`؛ لا اختبارات في Cloud Build قبل migrate/deploy؛ `max-instances=1` لكلٍّ (نقطة فشل واحدة، لكنها ضرورية حالياً لأن SSE/rate-limit/cooldown في الذاكرة).
- **التقارير مالياً**: تجمع مبالغ متعددة العملات (YER/SAR/USD) كرقم واحد بلا تحويل.

## P2/P3 — ملخّص فئات (جودة/اتساق/أداء/تجربة — بعد الإطلاق)
- لا أمر test/lint/e2e/security موحّد بالجذر؛ Worker بلا اختبارات و**typecheck متجاوز صراحة** في صورته + install غير مقفل؛ لا CI gate على push لـmain.
- Google login: تحقّق aud فقط عند وجود `GOOGLE_CLIENT_ID`؛ لا timeout على tokeninfo.
- كلمة مرور 8 أحرف بلا تعقيد؛ لا MFA؛ لا lockout؛ لا CSRF token (اعتماد SameSite+CORS)؛ جلسة 24س بلا فصل idle/absolute.
- CSP بوضع Report-Only + `unsafe-inline`؛ حد JSON 10MB؛ rate-limits في الذاكرة.
- رفع الصور: تحقّق Content-Type فقط (لا magic bytes/scan)؛ لا حذف للملفات القديمة؛ مسار الكائن يكشف workspaceId.
- Mojibake عربي + BOM في `products.routes` الخلفي؛ كود ميت بعد return في `searchKnowledgeDetailed`؛ `@ts-nocheck` على صفحة التسويق؛ أسماء حالات غير موحّدة؛ `amount_yer` يخزّن عملات أخرى.
- الإصدار 0.0.0 (لا تمييز نسخ)؛ لا Metrics/Trace كامل من webhook إلى Meta message ID (الـOutbox لا يحفظ Meta message ID).

## الخطوط الحمراء قبل التسجيل العام (لا تفاوض)
1. **كل P0 مغلقة** (خصوصاً العزل والمالية).
2. **العزل**: Composite FK أو RLS + تفرّد معرّفات القنوات + اختبار HTTP بجلستين فعليتين لكل جدول حسّاس.
3. **المالية**: transactions + أقفال حقيقية (دفع/طلب/مخزون/رصيد) + أرقام طلبات ذرية + حجز نقاط قبل المزود.
4. **الخصوصية**: إيصالات غير عامة + مسار حذف/تصدير workspace + سياسة retention.
5. **الموثوقية**: idempotency ذري للرسائل + backup قبل migration + timeouts خارجية + trace كامل.
